# MOC Instructions Tutorial: From Parts List to Finished Build

If you have just started building, a MOC instruction file can look intimidating: grids everywhere, arrows pointing in every direction, part numbers you have never seen. In reality a MOC plan is no different from a set manual — it simply packs more information into each page. This **MOC instructions tutorial** breaks the reading process down step by step so you can open a file and start building.

## 1. Read the Step Diagrams First: Studs Up, Follow the Picture

The most common format for MOC instructions is a top-down view combined with layer-by-layer diagrams. Three rules cover almost everything:

- **Studs face up.** In a top-down view, every small circle is a stud. Parts are placed in that orientation — get one piece facing the wrong way and everything above it ends up crooked.
- **Arrows show the insertion direction.** A part goes where the arrow points. Curved arrows usually mean "clip it in, then press it flat."
- **Only the highlighted layer is new.** Each diagram highlights the newly added parts in a darker tone while existing parts appear lighter or as outlines. Focus on the highlight and ignore the rest.

If you see an "x2" or "x4" note, that step repeats the same sub-assembly several times. Build the sub-assembly once, then attach the copies to the main body — it is much faster than rebuilding in place.

## 2. How to Read the Parts List (BOM): Part Numbers Beat Names

Nearly every MOC plan ships with a parts list, or BOM. Once you can read it, you stop flipping back through the diagrams guessing at pieces. The usual fields look like this:

| Field | Meaning | Example |
| --- | --- | --- |
| Part Number | The part's design ID | 3001 (2x4 brick) |
| Qty | How many you need | 12 |
| Color | Color name or code | Red / 21 |
| Category | Part family | Bricks / Plates / Tiles |

When hunting for a piece, **go by part number first**. The same brick exists in countless colors and sizes and the names rarely line up exactly. Sort your parts into bags by number before you start, then pull them out step by step instead of digging through the whole pile.

## 3. Color Codes and Counting Studs

Colors in MOC instructions are written one of two ways: an English name such as Dark Bluish Gray, or the official LEGO color ID such as 85. The classic beginner error is eyeballing it — dark gray and light gray, or dark tan and orange-yellow, look very similar on a finished render, but mixing them up ruins the overall look. Check every color code against the physical part before you build.

Sizing works on a stud grid: a part's footprint is measured in studs, so "2x4" means 2 studs wide and 4 studs long. When you build a large base, count the studs first and then decide how many bricks to combine, so you do not discover halfway through that the dimensions do not line up.

## 4. Scaling a Model Up or Down: Big Is Hard, Small Is Harder

Rescaling a plan is where a lot of people get stuck. Two practical rules:

- **Scaling down (say 1:1 to 1:2).** You cannot simply swap every part for half-size. LEGO dimensions are discrete — there is no half-stud brick. Work out the total stud count first, then redistribute the parts, changing the building structure where necessary.
- **Scaling up (say 2:1).** This is comparatively easy: replace each 1x1 area with a 2x2 plate. But the internal structure and connection points have to be redesigned, or the model falls apart the moment you touch it.

The least painful route is to skip the math entirely: use an official or community-made parts list plus step diagrams, and look for other-scale versions of the same model in a community like BrickPlans. That is far easier than recalculating by hand.

## 5. The Four Mistakes Beginners Make Most

1. **Guessing at color.** No code check, and the finished model shows visible color shifts.
2. **Reversing the orientation.** Studs facing the wrong way means tearing it apart and starting again.
3. **Skipping the quantities.** You did not read the BOM properly and only notice the missing parts at the end.
4. **Going too big too soon.** Choosing a multi-thousand-piece build as your first project and abandoning it halfway.
